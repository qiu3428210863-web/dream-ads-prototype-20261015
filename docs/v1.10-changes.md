# v1.10.0 — Centered horizontal scrolling and working CRT compilation

## Confirmed failures in v1.9

1. The fragment shader used the integer remainder operator (`i % 3`), but the canvas requests WebGL 1 / GLSL ES 1.00. Khronos glslang 16.6.0 reproduces the failure: `ERROR: 0:17: '%' : not supported for this version or the enabled extensions`. The initialization catch then displays the original DOM and the independent CSS vignette. Increasing the curvature coefficient cannot affect that fallback. This corrects the v1.9 diagnosis that weak curvature alone explained the screenshot.
2. Wheel input called `Lenis.scrollTo` with its default `programmatic:true`. In the shipped Lenis 1.3.27 build, this causes `targetScroll` to follow the animated position on each frame. Adding successive wheel deltas to that moving value loses the outstanding destination. Input now uses `programmatic:false` with an explicit `lerp:0.12`, so destinations accumulate and the rail eases toward the actual intended distance.
3. The v1.9 wheel listener consumed vertical input anywhere in the showcase. It had no check for the position of the cards in the viewport.

## Reference site analysis

Re-read the publicly referenced Shader bundles on 2026-10-17:

- [Lens and compositing implementation](https://www.shader.se/_next/static/chunks/04kr7kd5riobb.js?dpl=dpl_AadA2KVJaJtKN5QXgQu1gAVrbmig)
- [Section effect configuration](https://www.shader.se/_next/static/chunks/0wb~eqgmow_3x.js?dpl=dpl_AadA2KVJaJtKN5QXgQu1gAVrbmig)

The lens function centers the UV coordinates, uses cubic radial displacement, then applies center compensation. For the border-free mode the relationship is:

```text
p = viewportUV - (0.5, 0.5)
r = length(p)
sampleUV = (0.5, 0.5) + p × (1 + k × r³) × (1 - 0.3655 × k)
```

The About Us section configuration contains lens distortion `0.16`, border mode `0`, motion blur `0`, and independent vignette intensity `0`. The reference renderer also blends section settings and adjusts the main compositing lens strength. Thus a single section coefficient does not describe every reference frame. The formula above is the directly verified lens relationship; this project uses `k=0.16` as a fixed calibration rather than cloning the site's complete scene and transition system.

The curved-screen impression during scrolling comes from content moving through this viewport-relative nonlinear mapping. A horizontal line at different screen heights acquires different curvature. It does not require scroll speed to darken the vignette or oscillate the distortion. The v1.9 aspect-scaled quadratic formula has been replaced with the cubic UV-space relationship from the reference.

## Changes

- Compute the document scroll position at which the center of the first full card aligns with the center of the screen area below the navigation. Before that position, vertical wheel input continues scrolling the page normally.
- Clamp wheel-driven vertical scrolling when it crosses that position. While centered, wheel input moves the horizontal track. At the right end, onward input scrolls down; at the left end, backward input scrolls up. Horizontal touchpad input at a boundary also hands off to the page.
- Preserve touchpad horizontal distance, apply a modest `1.25` gain when translating vertical wheel input, and smooth with `lerp:0.12`. Mouse dragging stays one-to-one; release velocity is smoothed and capped at `0.65` card spacing for a short glide.
- Fix GLSL ES 1.00 compatibility with floating-point `mod`. CPU hit testing and GPU rendering use the same lens relationship. Apply subtle vertical RGB separation before hover compositing, preserving the CD's full color channels.
- Cache the main page and the long card rail in separate textures. Added cards no longer force the entire page into a wider, lower-resolution texture. Both caches are generated only on initialization or relevant layout/content changes; scrolling only updates shader uniforms and the shared animation frame.
- Keep the top navigation outside the lens; keep the existing light, constant edge vignette. Expose initialization failures through `data-crt-error` in addition to the existing status and console warning.

## Verification

- `npm run check`: JavaScript syntax checks and five behavior tests pass. Tests execute the shipped Lenis build and the actual application scroll setup against a controlled DOM fixture. They cover pre-center vertical scrolling, center pinning, cumulative wheel distance and post-input glide, both boundaries, reverse re-entry, horizontal-to-vertical touchpad handoff, line-unit normalization, and fractional touchpad input.
- `npm run check:shaders`: the actual embedded vertex and fragment shaders compile and link as GLSL ES 1.00 with Khronos glslang 16.6.0. The old fragment shader fails the same compiler with the remainder-operator error above.
- `git diff --check`: passes.
- Local browser rendering remains blocked by the browser tool's security policy. These results verify behavior logic and shader-language compatibility; they are not a browser screenshot, FPS measurement, or visual claim of exact parity with the reference. Native touchscreen momentum and browser/driver-specific rendering still need browser verification.

For shader validation on another machine, obtain [Khronos glslang 16.6.0](https://github.com/KhronosGroup/glslang/releases/tag/16.6.0), place its executable at `.tools/glslang/bin/glslang.exe`, or set `GLSLANG_VALIDATOR` to its absolute executable path. `.tools/` is ignored by Git; no compiler binary or user recording is included in the source release.
