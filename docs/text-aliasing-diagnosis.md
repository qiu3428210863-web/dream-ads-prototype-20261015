# 曲面文字锯齿复查与回退

2026-10-17。按用户要求撤销 v1.12 的采样优化，运行代码恢复到 v1.11.0。保留此前提交和 v1.12 报告作为历史记录，不代表它仍在启用。没有改动卡片数量、居中缓入固定、横向惯性与边界交接逻辑。

## 结论

上一轮优化对象选偏了：提高了位移控制图的坐标精度，没有提高正文的栅格化分辨率，也没有实现正文的超采样抗锯齿。用户观察不到文字清晰度改善，与代码实际变化一致。位移图精度可能影响几何平滑，但不能代替正文图像质量。

## 代码中的实际链路

1. `dist/crt.js:6–9` 把 main 和 footer 放进真实 DOM 的 crt-surface，再放进固定的 crt-viewport。导航栏在外面。
2. `dist/crt.css:9` 对整个 viewport 设置 `filter:url(#crt-lens)`。因此正文、按钮、卡片标题和图片均成为滤镜输入。
3. `dist/crt.js:11` 中，`feDisplacementMap in="SourceGraphic"` 对浏览器提供的正文图像进行位移采样。浏览器需先把图形转换为 RGBA 栅格，再做滤镜操作；这不是对字形轮廓直接做矢量弯曲。
4. 同一行的 `feGaussianBlur` 输入是 `field-raw`，只平滑位移控制图，不是正文。它不会为正文补充抗锯齿。
5. `dist/lens-model.js:9–15` 生成的 96×96 Canvas 只编码移动方向与距离。页面文字和产品图片没有被画入这个 Canvas。因此不能把 96×96 理解为“整个网页只有 96×96 分辨率”。
6. `dist/crt.js:35–37` 和 `dist/crt.css:12` 以浮点位置移动内容。曲面逆向采样也是连续坐标，因此滚动时像素落点持续变化，文字细边容易呈现闪动、台阶感。这里是有待浏览器画面对照验证的质量风险，不能仅凭源码确定严重程度。

## 为什么 v1.12 没解决

| 上次修改 | 实际作用 | 没有完成的工作 |
| --- | --- | --- |
| 按 DPR 加密位移图 | 更精确地表达每个位置的偏移 | 没有提高 SourceGraphic 正文像素密度 |
| 缩小位移编码范围 | 减少 8 位坐标量化误差 | 不会重新生成更清晰的字形边缘 |
| `image-rendering:optimizeQuality` | 给浏览器质量提示 | 没有实现可控的双三次采样或多点采样 |
| 字体平滑属性调整 | 在适用的平台影响字体绘制 | 相关非标准属性仅适用于 macOS，无法作为 Windows 的修复 |
| 位移误差 RMS 测试 | 验证数学坐标重建精度 | 没有测量文字锯齿、浏览器滤镜中间图像或帧率 |

因此，上次报告中的坐标误差改善不能当作视觉改善证据。

## 进一步放大问题的局部样式

`dist/showcase.css:55` 给卡片画面大字设置 `perspective(650px) rotateY(-9deg) rotateZ(-4deg)`，悬停时还改变角度与位置。这些斜向字边再进入全局曲面滤镜，增加了重采样风险，能解释卡片大字比普通水平正文更敏感，但不能解释所有正文问题。

曲面模型中心附近逆映射倍率为 `1 - .3655 × .16 = .94152`，对应输出局部放大约 1.062 倍。即使内容在屏幕中心，也不等于逐像素原样显示。暗角是独立覆盖层，不负责文字几何采样。

## 已确认与未确认

已确认：整页正文经过 SVG 位移滤镜；上一轮没有正文高分辨率渲染目标、显式超采样及降采样步骤；字体平滑设置不构成 Windows 修复；卡片大字叠加透视旋转。

尚未确认：用户浏览器实际分配的 SourceGraphic 像素尺寸、设备缩放与页面缩放、具体插值实现、各因素对当前锯齿的占比。当前没有获得用户浏览器的像素对照与渲染记录，不能把“某个低分辨率缓冲区”说成已经实测的唯一根因。

## 正确的下一步验证

应在相同浏览器、缩放比例和视口下，逐一对照关闭全局位移、取消卡片大字透视、保留曲面但去掉位移图量化这几种情况，并比较静止与滚动中的文字。若主要损失来自正文重采样，修复需针对正文输入分辨率、内容采样和最终降采样，而不是继续加密控制图。若采用独立 GPU 渲染，还必须先解决直接双击 HTML 时的本地资源读取兼容问题；单纯部署到 GitHub 也不会自动提高 SVG 文字采样质量。

本次仅回退和诊断，没有加入另一套未经画面对照验证的画质方案。
