本轮用户确认：通过**双击本地 HTML** 查看页面，也就是 `file:` 协议。

旧 `grayImage()` 先创建 `Image` 载入本地 SVG，再 `drawImage()`，最后调用 `toDataURL()`。后续整个曲面初始化依赖这一步成功。现代浏览器通常把 `file:` 文档视为不透明来源，同目录的文件也不保证同源；本地图片进入 Canvas 后，可能使读回操作抛出安全异常。该行为及 Canvas 读回限制见 [MDN 文件来源说明](https://developer.mozilla.org/en-US/docs/Web/Security/Defenses/Same-origin_policy#file_origins)和 [Canvas 跨源图片说明](https://developer.mozilla.org/en-US/docs/Web/HTML/How_to/CORS_enabled_image)。

**证据边界：**已经确认使用方式和代码依赖，且该路径与“普通内容仍可见、只剩暗角”吻合；没有取得用户浏览器的控制台异常，因此不把某条 `SecurityError` 声称为用户机器上的实测日志。v1.11 移除了整条产品图片读回/截图依赖，直接消除这个失败条件，而不是继续调整一个可能尚未启动的 shader 的曲率。

## 当前采用的曲面链路

`lens-model.js` 的固定镜头关系仍沿用此前核实的参考关系：

```text
p = viewportUV - (0.5, 0.5)
r = length(p)
sampleUV = (0.5, 0.5) + p × (1 + 0.16 × r³) × (1 - 0.3655 × 0.16)
```

这是一个以屏幕中心为原点的非线性采样场。内容在纵向或横向移动时经过同一片固定镜头，靠近边缘的直线会逐步弯曲；暗角只是独立的明暗层。镜头模型与前端来源分析保留在 `crt-analysis-v1.2.md`，本版不增加滚动速度驱动的黑边或强色差。

新的启动过程：

1. 把主内容和页脚放入一个固定、裁剪到视口大小的 `.crt-viewport`，顶部导航和原生 dialog 保持在外。
2. 用独立 spacer 保留正文原来的文档高度。滚动位置由现有 Lenis 驱动，真实 DOM 每帧只更新一个平移量，锚点和卡片逻辑沿用现有坐标。
3. Canvas 仅写入数学计算出的 R/G 位移值，再生成内存 PNG；没有产品图片、网络图片、字体或页面像素进入读回操作。图片仍由原生 `<img>` 显示。
4. `feDisplacementMap` 的输入是当前可见的 `SourceGraphic`。过滤区域固定为当前视口，不再随着整张长页面扩大；滚动时不重新生成位移图、不截图、不上传纹理。
5. 使用低分辨率、平滑插值的 96×96 位移场，并只对**位移场**做轻微平滑，不模糊页面文字。移除额外 RGB 分离，减少此前彩边和台阶感的来源。
6. 保留点击坐标映射、键盘焦点可见性处理、窗口尺寸变化、正文高度变化以及打印样式。真实 DOM 的 CD 悬停、内容变化和动画不再需要截图重建。

这恢复了此前可工作的直接 DOM 曲面路径，同时把滤镜处理对象从长页面改为可见视口。它是结构上的性能限制，尚不等同于已实测的帧率提升。

## 为什么此前到中间会突然卡住

v1.10 的每帧逻辑在检测到滚动越过停靠点后，立即调用 `pageScroll.scrollTo(carouselPinY, {immediate:true})`。这会直接截断纵向速度；即使其他滚动使用了 Lenis，这个停靠动作仍是即时的。

v1.11 改为在输入目标将越过停靠点时，就启动一次持续约 **0.28～0.6 秒**的 ease-out cubic 减速抵达。停靠点仍是卡片中心与导航下方视口中心对齐的位置。

- 抵达过程中继续滚动，不重启动画，也不立即横移卡片；输入距离暂存。
- 停靠完成后，剩余距离交给横向轨道原有的轻惯性缓动。
- 反向滚动可以取消抵达过程；键盘导航、锚点导航和打开模态窗口会清除停靠状态。
- 到横向边界后继续向外滚动，恢复纵向页面滚动；反向回到该区块时同样减速抵达。

## 验证与边界

- `npm run check`：JavaScript 语法检查和滚动/曲面行为测试。
- 滚动测试执行实际打包的 Lenis 与真实应用滚动代码，检查中线前的纵向滚动、减速抵达、多帧速度下降、距离传递、反向取消、边界衔接和小幅触控板输入。
- 曲面测试执行实际镜头模型与实际 `crt.js` 初始化。DOM fixture 以 `file:` 协议运行，刻意不提供 `Image`、html2canvas 或 WebGL API，并禁止 `drawImage()`；仍须进入 `svg-live-viewport / ready` 状态。
- 验证桌面/手机尺寸的编码误差、滤镜范围、导航隔离、亚像素滚动同步、滚动时不重建位移图、正文高度变化及 HTTPS 初始化路径。
- 本轮仍未通过浏览器工具打开本地页面；上述是模型、初始化与行为测试，并非浏览器画面截图，也不是实体设备 FPS 结果。浏览器 SVG 合成性能和最终视觉仍需实际浏览器验证。

## GitHub 部署兼容

当前入口与全部样式、脚本、产品资源使用相对路径，启动脚本为 classic deferred scripts，未引入依赖本地服务或跨源模块加载的路径。后续发布完整 `dist/` 即可作为静态托管内容。此次仅继续保存 Git 源码版本；没有开启 Pages、更改仓库可见性或创建部署凭据。

历史 html2canvas 资源和 shader 检查入口保留用于回溯。当前页面不加载 html2canvas；旧 `check:shaders` 命令转为调用新的镜头测试，编译器不再是运行或验证当前渲染器的必需工具。
