# 老电视曲面屏：原站前端分析与复刻

日期：2026-10-16。对应版本：v1.2.0。

## 结论

录像中的网页是 [Shader Development Studio](https://www.shader.se/)。核对公开前端代码后，可以确认：曲面不是一张暗角图片，也不是 CSS 的 perspective/rotateX，而是界面纹理经过径向坐标重采样，再叠加色差、颗粒、色调和其他后处理。中心缩放补偿是关键；只给边缘施加几像素的位移，无法得到相同的凸面感。

按用户最新反馈，本版使用固定曲率和固定暗角：滚动时内容经过同一块“弯曲玻璃”，暗角不随滚动速度或页面位置变暗。已移除先前尝试中的速度驱动暗度与曲率逻辑。

## 输入与分析方法

用户提供的 MP4：2524×1324，30fps，252 帧，时长 8.4 秒。本地读取并按时间抽取 16 帧，未修改原视频，也未将用户录像上传到第三方服务。之后依据画面中的品牌与标题定位官网，读取其公开 HTML 和实际引用的前端脚本。

录像中 0–3 秒可观察到内容滚动经过屏幕边缘；约 6.7–8.4 秒画面停留时，彩色横线仍呈弧形。这说明曲面有常驻的镜头坐标变换，而不是纯滚动拉伸。原站的公开配置还说明：镜头和后处理按页面区段配置，并不等同于“滚得越快暗角越黑”。

## 已核实的原站实现

### 渲染架构

原站使用 React Three Fiber / Three.js，创建 WebGPURenderer，并在不支持 WebGPU 时启用 WebGL 后端。界面分为 UI 纹理与场景纹理，再经 FBO/后处理合成；公开代码还包含亮/暗 UI 纹理与 UI 遮罩。因而文字、图片、分隔线、导航都可以进入同一镜头空间。

公开资源：

- [镜头函数、合成场景和后处理实现](https://www.shader.se/_next/static/chunks/04kr7kd5riobb.js?dpl=dpl_AadA2KVJaJtKN5QXgQu1gAVrbmig)
- [页面分区与效果配置](https://www.shader.se/_next/static/chunks/0wb~eqgmow_3x.js?dpl=dpl_AadA2KVJaJtKN5QXgQu1gAVrbmig)

资源名是分析时页面实际引用的构建版本；原站日后发布可能更换这些地址。本项目未复制整包脚本或迁入原站业务代码。

### 几何曲面：先以屏幕中心为原点，再非线性采样

将屏幕坐标标准化为 `uv`，设中心为 `c=(0.5,0.5)`：

```text
p = uv - c
r = length(p)
q = 1 - 0.3655 × k
sampleUV = c + p × (1 + k × r³) × q
```

这里是对已核实计算关系的数学整理，不是原站压缩代码的粘贴。

- `r³` 让中央区域变化小、外围变化明显。均匀 scale 只能改变大小，无法让一根直线弯曲。
- `q` 是中心缩放补偿。原站无黑框模式会把采样坐标向中心收拢，抵消桶形镜头对边缘的影响；视觉上中央内容被放大，四周收拢，产生凸起的玻璃感。
- 原站相关区段的 `lensDistortion` 为 `0.16`，全局镜头因子默认为 `1`，无边框模式为 `0`。本版沿用这组镜头参数。
- X、Y 是 UV 坐标。换成实际像素时，必须分别乘屏幕宽和高；两轴共用一个固定像素位移量，会把横向弯曲严重缩小或改变形状。
- 曲面必须以当前视口为中心。把整张长网页从顶到底作为一张畸变图，会使屏幕中间区段几乎不变形，效果与原站不同。

### 边缘遮罩和暗角

原站另有 UV 边界平滑与圆角距离场边界处理，以及独立可配置的暗角半径、平滑度和强度。须区分：镜头边缘遮罩、独立暗角、图片本身的灯光和纸色，不是同一效果。公开配置中，有些正文区段的独立暗角强度就是 0，因此不能把录像的全部边缘变化解释成一张随滚动加深的黑色渐变。

本版按用户要求，仅保留固定的柔和玻璃暗角。中心保持透亮，外围和四角渐暗；CSS 暗角强度固定为 `.28`，JS 没有修改该值的代码。

### RGB 分离

原站后处理中，各颜色通道在略有偏差的位置采样，并对 UI 遮罩附近减弱偏移；公开代码以垂直方向的微小偏移为主。黑色文字边缘因而出现细微红蓝轮廓，强化模拟显示器的光学感。

本版在曲面采样后分离 RGB：红色上移约 0.42 CSS 像素，绿色保持原位，蓝色下移约 0.42 像素。幅度固定，不随滚动放大。保留三通道合成前的实色页面底，避免半透明导航被错误合成为灰黑矩形。

### 颗粒、色调、辉光和运动历史

原站存在颗粒、褐色调、饱和度/对比度、亮度/幂次、bloom 以及运动历史混合相关的后处理；不同页面区段配置不同。这些解释了录像的旧纸色、模拟影像和高光质感。它们不是曲面几何本身。

本版保留现有白粉品牌配色，只加低强度固定颗粒与轻微玻璃光感；没有把页面整体染成录像里的黄褐色，也没有增加强扫描线或画面拖影。

## 本项目的复刻方式

复刻的是原站的镜头数学行为和显示质感，渲染后端使用 SVG 滤镜，而不是把整站迁移到 Three.js 画布。

1. 保留原有 DOM、原生滚动、锚点和所有业务按钮。
2. 把导航、主内容、页脚纳入 `.crt-surface`；顶层 dialog 保持在外面，避免表单受镜头影响。
3. 页面初始化及视口尺寸改变时，用 Canvas 按上面的公式生成位移场。R 保存横向位移，G 保存纵向位移；只是生成数学数据，不截取/复制网页图片。
4. 以 SVG `feDisplacementMap` 对真实页面像素重采样，再合成微弱 RGB 色差。
5. 滚动只更新滤镜采样窗口的 Y 位置，不修改曲率、不修改暗度。
6. 在视口上下各保留半屏的预绘制区，避免浏览器合成线程先于 JS 滚动时出现画面裁断。
7. 单独的固定 `.crt-glass` 绘制暗角和颗粒，`pointer-events:none`，不拦截点击。

SVG 位移滤镜的通道与 `scale` 语义可参考 [MDN feDisplacementMap](https://developer.mozilla.org/en-US/docs/Web/SVG/Reference/Element/feDisplacementMap)。本版先将 UV 差换算成像素，再编码为通道值，因此 `scale` 数值随视口尺寸变化，但实际几何曲率 `k` 始终是 `0.16`。这不是滚动强度变化。

## 文件与调节位置

| 文件 | 作用 |
|---|---|
| `dist/crt.js` | 镜头公式、位移数据生成、SVG 通道合成、视口对齐 |
| `dist/crt.css` | 固定暗角、颗粒、弹窗层级、减少动态效果及打印降级 |
| `dist/assets/crt-grain.svg` | 低强度颗粒纹理 |
| `dist/assets/crt-displacement.png` | 初始后备位移图；运行时按实际宽高生成精确版本 |

调曲率看 `lensDistortion`；调暗角看 `--crt-vignette`。二者已完全解耦。没有速度控制器，也没有暗度呼吸动画。

## 验证与限制

- 桌面验证镜头实际应用于导航、标题、图片和卡片；静态页面也有弧线，滚动时内容经过同一固定曲面。
- 首屏与滚动后，读取到的暗角值均为 `.28`，曲率均为 `.16`。
- 分类筛选和概念预览弹窗仍正常；手机菜单与报名弹窗单独验证。
- 视口滤镜有两屏高度的预绘制范围，不依赖截取整张长页面的图像。实际 FPS 未做硬件矩阵测试，不能把实现策略当成性能跑分。
- 支持 reduced-motion：关闭几何变形和颗粒，保留较轻固定暗角；打印时移除镜头。此分支通过代码检查，未模拟系统设置做跨浏览器测试。
- 当前在 Chromium 内核浏览器实测；Safari/Firefox 尚未逐一验证。
- 整页长截图与视口镜头概念不同，若要导出整页，应使用打印样式或关闭镜头；已保存的效果图为真实视口截图。

这是一版基于原站公式的 DOM 适配复刻，不宣称与原站 WebGPU 帧缓冲、字体纹理和全部光学后处理逐像素一致。
